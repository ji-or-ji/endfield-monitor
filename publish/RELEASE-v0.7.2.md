# EndfieldMonitor v0.7.2

> 这一版只改采集端的 Linux 侧，其余与 v0.7.1 一致。

## Linux 采集端：修正主网卡误判，补上真实链路速率

这是采集端第一次放到真实的 Linux 机器上跑，验证时揪出一个只在 Linux 上才会犯的错。

- **主网卡被误认成回环 `lo`**。判回环原来看的是接口名字前缀 `Loopback`，那是 Windows 的叫法；
  Linux 的回环叫 `lo`，不带这个前缀，于是 `lo` 被当成了主网卡，网络那一路的读数全错。
  现改为认接口的 `loopback` 标志位，名字只作兜底（`lo` / `lo0` / `Loopback…`）。
- **链路速率改读 sysfs**。Linux 下改从 `/sys/class/net/<网卡>/speed` 直接取真实速率（Mbps），
  取不到才退回 1000 估算，不再一律写死 1000。

### 已验证

- 在 **Linux Mint 22.3** 虚拟机里跑 `enf-collector-v0.7.2-linux-x64`：
  主网卡正确识别为 `enp0s3`（此前为 `lo`），`/snapshot` 的 `net` 段连续三次读数一致。
- 电池项在虚拟机里报「有电池、充电中」，经核实是 VirtualBox 给 guest 的虚拟电池 `BAT0`，
  属正确采集，不是误报。

## 已知不稳 / 还没做

- Linux 侧这次只验证了采集端（普通版）的核心读数；**增强版的启停与取图标**、
  更新替换脚本、客户端界面，仍未在 Linux 真机上逐一验证。
- 依赖 WMI 的项（内存条型号、磁盘介质、显卡、计划任务）在 Linux 上本就留空。
- 采集端采到的 `net.link` 在这台虚拟机里恰好也是 1000，与估算值相同，没法借它区分新旧路径。
