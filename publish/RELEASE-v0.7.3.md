# EndfieldMonitor v0.7.3

> 这一版把 Linux 侧的应用图标接了过来：采集端优先给位图，客户端自带 XPM 解码。

## Linux 应用图标：优先取位图，脚本应用按真身认

上一版验证 Linux 采集端时，客户端一直显示不出 Linux 的应用图标。
补这一环时挖出三层问题，都不是「取不到」，而是「取回来了却用不了 / 认错了」。

- **矢量图标客户端画不出来**。增强版把图标文件原样转发给客户端，而 Linux 图标大多是
  SVG / XPM，位图解码器啃不动，只能退回字形。现在采集端**先只找 PNG**，找不到才退回
  SVG / XPM——不少图标本来就备着 PNG，此前被优先命中的 `scalable/` SVG 白白盖掉了。
- **客户端自带 XPM 解码器**。XPM 是纯文本像素图，手写一份解出来，不引第三方库，装好即用。
- **脚本型应用认错了图标**。`cinnamon-settings`、`mintUpdate` 这类是 python 脚本，
  可执行文件都是 `python3.12`，于是全被认成 Python、顶着同一个图标。现在采集端改从
  **argv** 里取应用的「真身」名字，解释器本身不再作为候选；`Exec=` 里
  `env VAR=val prog` 这层包装也一并穿透。
- **缓存键修正**。图标缓存原按可执行文件路径做键，而脚本应用共用解释器这个 exe，
  会被第一个解析结果吞掉（四个应用返回同一个图标）。现在服务端与客户端的缓存键都带上进程名。

### 已验证

- 在 **Linux Mint 22.3** 虚拟机里跑增强版采集端，Windows 客户端跨机查看：
  `csd-*`、`mintreport-tray`、`mintUpdate` 等各行取回各自的真图标，
  此前顶着 Python 图标的脚本应用也各归各位。
- 只有 SVG、没有 PNG 的图标（如 `cinnamon`）仍退回字形。

## 已知不稳 / 还没做

- 客户端仍画不了 **SVG** 图标，这类行会退回本地字形。
- 采集端「取窗口标题」的启发式仍可能抓错（例如 `explorer.exe` 会取到任务栏辅助窗口的标题）。
- 依赖 WMI 的项（内存条型号、磁盘介质、显卡、计划任务）在 Linux 上本就留空。

## 下载

见本发行版附件。平台 win / linux，架构 x64 / arm64。
套件（bundle）里客户端与采集端同目录即可，客户端会自动拉起采集端。
