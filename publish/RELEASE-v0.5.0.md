## 这一版的三件事

1. **本机自看变成一步**：客户端地址留空即连本机；套件形态下它还会**自己把采集端拉起来**
2. **自包含套件**：每个平台一个 zip，客户端 + 增强版采集端 + 一份怎么用
3. **增强版补了四样**：Flatpak 图标、图标缓存、进程启动参数、操作审计

## 本机自看：一个文件夹，双击一个

发行版里每个平台多了一个 `*-bundle.zip`：

| 平台 | 套件 |
| --- | --- |
| Windows x64 | `EndfieldMonitor-v0.5.0-win-x64-bundle.zip` |
| Linux x64 | `EndfieldMonitor-v0.5.0-linux-x64-bundle.zip` |
| Linux arm64 | `EndfieldMonitor-v0.5.0-linux-arm64-bundle.zip` |

解压后**打开客户端就行**——它会先探一下本机 8898，没人监听就把同文件夹里的采集端拉起来，
然后连上。不需要开第二个窗口。

- 本机已经在监听就不重复拉起（你自己开了一个当被监视端给别人看的话）
- 客户端退出不去动那个进程：它可能正被别人看着
- 只拿了客户端（没带 zip 里那个采集端）时，地址留空仍然连本机，只是不拉起
- Linux 上客户端会先补一次执行位（zip 不保留 Unix 权限）

## 增强版（plus）这一版的增量

| 项 | 说明 |
| --- | --- |
| Flatpak 图标 | 这类进程的 exe 是 `bwrap`，按名字匹配不上；改读 `/proc/<pid>/environ` 的 `FLATPAK_ID` |
| 图标缓存 | 按 exe 路径缓存。实测同一 pid 连请求两次：47 ms → 3 ms |
| 进程启动参数 | 快照里带 `cmd`。**只在增强版采**，因为命令行里可能带着口令之类的参数 |
| 操作审计 | 最近 50 条：时间、动作、pid、进程名、来源地址、结果；没动过手时这个键不出现 |

## Linux 图标这条链补齐的地方

- 按规范的 pseudocode 解析主题的 `index.theme`（`Directories=` 与每个目录的尺寸属性），
  布局非常规的主题（如 `48x48@2/apps`）现在也能找到
- 图标尺寸优先顺序修正：原来把 256x256 排最前，而客户端按 38px 显示，应该先找 48
- 对照 Icon Theme Specification 0.13 核过一遍，两处有意偏离（hicolor 优先等）在代码注释里
  写明了理由
