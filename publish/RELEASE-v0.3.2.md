## 本版做了什么

### CPU 频率读数修好了

**症状**：不管负载多高，频率都不超过基准（2.10 GHz），看着像是被锁死了。

**查下来的原因**：几个"频率"接口给的口径都不对。

| 来源 | 实测表现 |
| --- | --- |
| `Processor Frequency` 计数器（原来用的） | 各核当前频率的**加权平均**：8 个 P 核线程 2.1G + 4 个 E 核线程 1.54G 时，平均正好 1913 MHz。大小核混在一起，睿频被平均掉了 |
| `CallNtPowerInformation` | 只报**静态基准**：P 核一律 2100、E 核一律 1540，单线程满载也纹丝不动 |
| WMI `CurrentClockSpeed` | 同样只报 2100 |
| `% Processor Performance` | **活的**：空闲 ~60%，全核满载稳住 ~152% |

**改法**：实时频率 = 基准 × `% Processor Performance`（100% 即基准）。实测结果：

- 空闲：1.1 ~ 1.5 GHz
- 全核满载：稳定 **3.19 GHz**（基准的 152%）
- 峰值：**4.61 GHz**，正好是这颗 i5-13420H 的睿频上限

顺带说明：电源计划那边已经排除了（最大处理器状态 100%、睿频模式「高性能」、`PROCFREQMAX` 为 0 即不限），不是被系统锁住的。

### 设备详情面板不再定格

以前详情行在设备行建立之后就再没更新过，打开面板时又拷了一份，于是彻底冻住——会出现"行上写着 3.18 GHz，详情里却说尚未观测到超过基准"这种自相矛盾。

- 详情行改为可观察对象，面板直接复用行自己的实例，打开后随快照实时刷新
- 同步刷新的项：处理器**实测峰值**、显卡利用率与显存、磁盘已用、电池电量/状态/剩余时间
- 去掉了面板底部与列表行重复的「占用 / 速度」两行
