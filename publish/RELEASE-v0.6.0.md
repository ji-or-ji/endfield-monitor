## 这一版加了自动更新

客户端能自己发现新版本了。设置里勾上「启动时检查更新」，默认是关的。

| 形态 | 行为 |
| --- | --- |
| **套件版**（同目录带着采集端） | 启动时比对发行版，发现新版自动下载，出现「立即更新并重启」，点一下换好 |
| **分布部署**（采集端在别的机器上） | **只提示**，并说明是客户端还是采集端旧了，给一个「打开发行版页面」 |

换文件这件事有个绕不过去的点：Windows 上运行中的程序不能覆盖自己。所以实际动作是
「下载 → 解压 → 客户端退出 → 一段临时脚本停掉旧采集端、备份、换文件、起新版」。
旧版留 `.bak` 一份，换坏了能退回来；只保留一代备份，不会越攒越多。

**检查更新失败不影响任何功能**：没外网、超时、接口变动，一律当"没有新版本"，
而且开关默认关着，不打开就不会连任何外部地址。

### 版本号现在两端都自报

- 采集端在快照的 `server.collector_version` 里报自己的版本，客户端靠它判断**分布部署时该更新哪一端**
- 两端的版本号都在构建时注入（客户端 `-p:Version=`，采集端 `-X main.version=`），源码里直接跑就是 `0.0.0` / `dev`

## 发布流程也改了

- **Gitee 是主仓库**：发行版只保留最近两个版本（附件配额 1 GB，全量发几版就会满）
- **GitHub 是代码镜像**：只同步代码与标签，不挂产物（本地网络到 GitHub 太慢，实测单次 API 调用约 3 秒）
- 需要旧版本的请在 issue 里提
- 发布脚本 `build.ps1` 一条命令做完：构建九份产物、打三个平台的套件包、双平台推送、建发行版、全量上传

## 附件说明

- **客户端**：`win-x64` / `linux-x64` / `linux-arm64`
- **采集端**：普通版与增强版各三平台
- **套件**：三个平台各一个 zip（客户端 + 增强版采集端 + 怎么用）

另附 `SHA256SUMS.txt`。
